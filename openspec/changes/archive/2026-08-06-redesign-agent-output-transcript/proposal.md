## Why

现有聊天视图将 Claude 的文本、工具调用和过渡状态平铺为独立消息；工具条目只保留原始输入，用户难以判断一次请求在做什么、产生了什么结果，也会在长回合中被重复的过程文案打断阅读。需要将界面改为面向开发任务的回合级执行记录：答案保持易读，Claude Code 的执行过程保持可追溯。

## What Changes

- 将一次用户请求及其后续助手文本、工具活动、系统通知和终止状态组织为有序的输出记录，并兼容既有会话历史。
- 为连续工具操作提供可折叠的活动组：使用面向用户的摘要展示文件读取、搜索、编辑、命令执行与失败状态；用户可按需查看受限的原始输入、输出或变更详情。
- 基于 Claude CLI 实际事件展示生成中状态、任务进度、上下文压缩与重试信息；事件不可得时明确降级，不凭工具数量或推测结果伪造进度或完成状态。
- 调整聊天视图的流式跟随策略，使用户阅读历史时不会被新输出强制拉回底部，并保留跳转到最新输出的操作。
- 所有客户端拥有的活动和状态文案遵循当前语言；Claude 回复、工具原始内容、路径和命令保持原值。

## Capabilities

### New Capabilities

- `agent-output-transcript`: 将一次请求的输出按回合和时间顺序记录、恢复并呈现为正文、活动与通知。
- `tool-activity-details`: 关联工具调用与可用结果，生成安全的活动摘要并提供按需展开的技术详情。

### Modified Capabilities

- `gui-chat`: 将消息列表的工具调用和流式状态展示改为可阅读、可追溯且不抢占用户滚动位置的聊天工作区。

## Impact

- 影响 Claude CLI 事件归一化、共享传输类型、回合组装器、会话 JSON 迁移与主进程/渲染层对同一提交流的消费。
- 影响 `ChatView`、消息渲染组件、状态显示、滚动行为、国际化词典和相关测试。
- 不改变 Claude CLI 的模型、项目目录或默认授权模式；逐操作权限和完整执行详情仅在底层传输明确支持时启用。
