## Context

参见 `proposal.md`。当前 `AgentEvent` 只表达文本增量、工具调用、单一状态和终止事件；`streamParser` 忽略 `user` 事件并未保留工具调用标识，因此无法可靠关联工具结果。现有 `TurnAssembler` 虽能保证文本与工具调用的到达顺序，却将它们提交为彼此独立的 `Message`。主进程和渲染层各消费同一规则，但各自生成标识；会话存储为可原子替换的本地 JSON，已具备追加和更新消息的能力。

## Goals / Non-Goals

**Goals:**

- 保持 Claude CLI 事件的真实语义和顺序，并让主进程持久化与渲染层状态使用相同的、带稳定标识的提交流。
- 在不依赖特定 Claude CLI 版本的前提下，按能力提供基础活动、关联结果、任务进度和系统通知。
- 让新记录支持安全详情、旧会话可读、生成中可追踪且完成后简洁。

**Non-Goals:**

- 不显示或推导隐藏推理内容，不嵌入 Claude Code TUI，也不复制其终端界面。
- 不在裸 CLI 传输上实现逐操作权限确认；现有会话级授权模式保持不变。
- 不保证恢复全部命令原始输出或把脱敏当作完整的秘密检测方案。

## Decisions

### 决策 1：用能力分级的事件归一化隔离传输差异

扩展传输事件为文本、活动开始、活动完成或失败、结构化状态、终止和会话初始化。每个活动开始事件携带提供方给出的稳定工具调用标识；活动完成事件必须携带能关联该标识的结果。状态事件携带类别，例如重试、上下文压缩或任务进度，而不是预先本地化的自由文本。

在实现前先以实际安装的 Claude CLI 版本采集并脱敏 `stream-json` fixture，验证 `tool_use` 标识、`tool_result` 载体、任务状态和系统通知的可用性。解析器仅转换 fixture 已证实的字段；未知字段安全忽略。传输暴露能力集：

- `basic-activity`：工具已发起和回合终止。
- `activity-results`：可关联的结果、错误、输出或确定的文件统计。
- `task-progress`：带完成数和总数的真实任务状态。
- `system-notices`：可展示的重试或压缩通知。

UI 根据能力集降级。缺少 `activity-results` 时活动不会显示为完成；缺少 `task-progress` 时不显示步骤进度。未来 ACP 或 Agent SDK 适配器可以提供更多能力，但不得改变输出记录和渲染组件的契约。

备选方案是在界面根据工具数量、后续文本或完成事件推断状态。该方案会产生错误的成功、文件统计和进度，因此拒绝。

### 决策 2：使用带顺序号的共享回合组装器

每次发送由渲染层生成 `turnId` 并随请求传给主进程。主进程为来自 runner 的每个已归一化事件分配递增 `sequence`，将 `{ turnId, sequence, event }` 同时送入其持久化组装器并经 IPC 转发给渲染层。组装器用 `turnId + sequence` 派生条目与活动标识，使两侧应用同一事件包时得到相同的提交顺序和可更新目标。

组装器将实时正文保留为内存缓冲，在活动、通知或终止边界冲刷为正文条目；活动开始先产生可更新活动条目，关联结果到达时更新同一条目。它产出的提交包含追加条目、更新条目、更新会话 CLI ID 和实时视图状态。主进程仍是磁盘写入者，渲染层只消费 IPC 提交，不再自行发明消息或活动 ID。

这比只在渲染层分组更可靠，因为刷新、重启和工具结果迟到时仍可保持同一回合结构；也比每次文本增量都落盘更少 I/O。保留单一组装规则优于主进程和渲染层各维护 reducer。

### 决策 3：引入规范输出记录并保留兼容投影

会话数据新增版本化的 `transcript`，其规范条目为用户请求、助手 Markdown 段、工具活动、系统通知和终止状态；每项都有 `id`、`turnId`、顺序号和时间。连续活动组是从同一回合中相邻工具活动派生的渲染视图，不单独持久化，避免折叠策略和数据顺序耦合。

既有 `messages` 字段在过渡期保留为兼容投影。读取不含 `transcript` 的旧会话时，客户端由旧消息生成只读历史条目；首次写入新版记录时，在同一原子写入中保存规范记录及可被旧版本显示的无损或降级消息投影。新渲染层优先使用 `transcript`，旧版本忽略未知字段后仍能阅读投影，代价是看不到活动分组和关联详情。

备选方案是就地扩大 `Message.role` 并只在渲染时猜测分组。它不能稳定表达活动生命周期和结果关联，也会让历史恢复依赖脆弱的相邻消息推断，因此拒绝。

### 决策 4：摘要优先、详情按需展开并在边界处脱敏

`TranscriptView` 由正文段、`ActivityGroup`、单项活动行、系统通知和回合终止状态组成。连续工具活动在生成中自动展开；获得终止状态并进入后续正文或回合结束后自动收起。失败、被中断或尚未获得结果的活动保持可见状态。工具类型映射为面向任务的摘要：文件读取、搜索、编辑、命令执行及通用活动；不能确定类型时显示工具原名和基础状态。

原始输入、输出、diff 与命令详情只在用户展开时显示。主进程在持久化前对原始详情施加每活动 64 KiB、每回合 256 KiB 的上限，并脱敏常见的授权头、令牌、私钥块和赋值式密钥。截断和脱敏作为元数据保留并显示。该规则降低本地历史中的意外暴露，但不替代用户对项目内容的访问控制。

### 决策 5：以阅读位置控制流式跟随

聊天滚动容器维护“接近底部”状态，阈值为距底部 96 px。只有该状态为真时，新增正文、活动或状态才滚动到锚点；否则保留 `scrollTop` 并显示带未读输出数量的“跳转到最新输出”按钮。用户点击按钮、手动滚到底部或切换会话时清除未读状态。

备选方案是沿用每次文本变化都调用 `scrollIntoView`。它实现简单，但会中断用户审阅长输出，故拒绝。

### 决策 6：客户端文案与传输内容分离

活动类别、状态、展开标签、截断提示和跳转按钮使用现有词典键。Claude 正文、工具名称、路径、命令、原始输入和输出作为数据渲染，不参加翻译。这样既满足本地化要求，也避免修改用户和工具实际内容。

## Risks / Trade-offs

- [不同 CLI 版本不提供可关联的工具结果] → 通过能力集展示基础活动，并用 fixture 测试每个支持版本；需要丰富结果时再启用 ACP/SDK 适配器。
- [主进程与渲染层的提交序列分叉] → 只转发带序号的事件包，并为同一 fixture 断言两侧产生相同条目 ID、顺序和最终状态。
- [迁移后新版与旧版消息投影不一致] → 将投影生成收敛在组装器提交处，读取时优先规范记录，并为旧会话、降级显示和原子写入失败建立回归测试。
- [大量工具输出增加 I/O 或暴露敏感数据] → 不按 token 落盘，限制原始详情大小、先脱敏再持久化，并在 UI 明示截断或脱敏。
- [活动自动展开造成滚动跳动] → 固定活动行的最小布局，在用户离开底部时不自动滚动；只对当前活动组做受控展开。

## Migration Plan

1. 先加入脱敏的 CLI fixture 和事件能力检测，确认基础活动路径；不改变现有会话文件。
2. 发布包含兼容读取、规范记录和消息投影的版本；旧会话在首次新版回合写入时以原子替换升级。
3. 启用新的输出视图并用现有历史会话、基础能力和丰富能力 fixture 做验证。
4. 回滚时旧客户端忽略 `transcript` 字段并显示 `messages` 投影；新记录的分组、通知和受限详情不再可见，但文本、工具调用和终止状态保持可读。

## Open Questions

- 当前支持的 Claude CLI 版本中，工具结果、任务状态和上下文压缩事件的实际字段形态与稳定性，需要在任务中的本地 fixture 探针确认。
