## Context

见 `proposal.md`。当前组合器仅有模型下拉和全局危险放行开关：模型缺少 CLI 别名，放行状态不属于会话；渲染层还会把临时授权值随发送 IPC 传给主进程。会话 JSON 已具备模型和项目目录迁移逻辑，但没有授权模式。当前 stream-json 传输只能通过 Claude Code CLI 的 `--permission-mode` 在调用前确定权限策略，不能可靠地暂停并回传每一次工具确认。

## Goals / Non-Goals

**Goals:**

- 让每个会话持久化一个经规范化的 CLI 授权模式，并让主进程以该保存值启动 CLI。
- 在组合器中清晰展示模型产品名、CLI 别名和授权模式，避免生成中的参数竞争。
- 以准确、可执行的输入状态反馈项目目录、CLI 可用性和生成状态。

**Non-Goals:**

- 不实现逐工具权限确认、远程授权服务或 Anthropic API Key 管理。
- 不修改 Claude Code CLI 的实际权限语义，也不在客户端安装或登录 CLI。
- 不改变既有会话消息、CLI 续接或项目目录语义。

## Decisions

### 会话为授权配置的唯一来源

在共享会话类型中定义 `PermissionMode`、默认值、可选项和规范化函数；会话索引和完整会话记录均保存该值。主进程仅允许 IPC 更新白名单中的 `title`、`model`、`permissionMode` 和时间戳，并在发送时读取保存后的会话配置，而不采信渲染层提交的权限模式。

这样能防止 UI 临时状态和实际 CLI 参数偏离，并让多会话切换与重启恢复一致。替代方案是保留全局开关并继续由发送 IPC 传参，但它不能表达每会话配置，也允许不受约束的渲染层值影响执行权限。

### 只提供传输层可以可靠执行的模式

选择 `acceptEdits`、`plan`、`dontAsk` 和 `bypassPermissions` 四个 Claude Code CLI 模式，并以 `acceptEdits` 作为新旧会话默认。进入 `bypassPermissions` 时使用现有模态确认交互；取消则不写入会话。

不提供 `default` 模式，因为它依赖逐工具提示交互，而当前 stream-json 传输无法可靠地呈现和回传该交互。也不保留只表达 UI 状态的 `auto` / `manual` 值。

### 控制项锁定与可读标签

模型和授权控件使用原生选择控件，以稳定支持键盘、可访问名称与小窗口布局。模型选项显示产品名和稳定 CLI 别名；授权选项显示简短中文标签。生成中两个控件均禁用。组合器状态函数同时判断项目目录和 CLI 状态，并映射为唯一、可测试的输入提示。

保留未知旧模型的可见回退项，避免历史数据在 UI 中丢失；存储规范化会继续将已知旧模型映射到稳定别名。

## Risks / Trade-offs

- [CLI 版本不支持某个权限模式] → 仅使用当前 Claude Code 支持的模式；CLI 错误仍走既有错误呈现路径。
- [旧会话不含新字段] → 读取时规范化为 `acceptEdits`，索引与单会话写回时包含新字段。
- [切换全部放行的风险] → 使用明确危险文案和二次确认；默认不使用该模式。
- [窄窗口控件拥挤] → 使用可收缩的元信息、固定按钮尺寸和可换行的控制区，避免发送按钮被挤压。

## Migration Plan

1. 扩展会话类型与读取规范化逻辑；缺少或无效授权模式时回退为 `acceptEdits`。
2. 将全局危险放行状态迁移为会话更新操作，并收紧 IPC 发送与更新载荷。
3. 替换组合器控制并更新提示与响应式样式。
4. 通过单元测试覆盖迁移、IPC 权威值、控件锁定和输入状态；发布后旧 JSON 在首次更新时自然写入新字段。

回滚时，新字段会被旧版本忽略；旧版本仍可读取已存在的会话核心字段。
