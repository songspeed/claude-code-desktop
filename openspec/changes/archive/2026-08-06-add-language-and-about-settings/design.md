## Context

现有外观偏好已通过主进程本地文件和受限 IPC 在渲染层恢复，但客户端语言仍是分散的硬编码中文文案。设置中心没有应用信息页；CLI 检测已在初始化时完成，但丢弃了版本字段。参见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 在 Electron 用户数据目录持久化一个受限的语言枚举，并支持多窗口同步。
- 让静态客户端文案从集中词典读取，覆盖设置、侧栏、搜索、空会话、组合器与确认操作。
- 为关于页面提供不包含密钥、路径或用户内容的运行时信息。

**Non-Goals:**

- 不翻译会话内容、Claude 输出、工具输出、模型 ID 或用户级 Claude 配置。
- 不引入第三方国际化依赖、在线翻译或地区格式化策略。

## Decisions

### 决策 1：将语言偏好作为独立本地设置

语言采用 `zh-CN` 与 `en` 的封闭集合，并保存在独立偏好文件中。主进程校验、保存并广播最终值，渲染层只通过 IPC 读取和更新。

复用 `appearance-preferences.json` 能减少文件数量，但会把独立设置生命周期耦合在一起；使用 `localStorage` 则与现有 Electron 设置边界不一致。

### 决策 2：使用轻量集中词典而非引入 i18n 框架

渲染层提供类型化文案键与中英文词典，页面通过当前 store 语言获取翻译。动态用户内容保持直接渲染，只有客户端固定文本进入词典。

当前字符串数量有限，额外依赖不能显著降低维护成本；集中词典仍能避免设置页面与侧栏切换语言时出现混合文案。

### 决策 3：关于信息由受限 IPC 提供

主进程返回应用名和版本、Electron 版本、平台及架构。CLI 可用性与版本沿用初始化检测结果放入渲染层状态，因此关于页不需要访问 shell、环境变量或 Claude 配置。

将完整进程环境或配置文件直接暴露给渲染层会扩大敏感信息暴露面，且对关于页面没有必要。

## Risks / Trade-offs

- [遗漏固定文案导致界面混合语言] → 将所有新旧客户端常用控制文案收敛进词典，并用静态渲染测试覆盖中英文关键页面。
- [语言偏好文件损坏] → 无效或缺失值回退到简体中文，不影响会话和外观偏好读取。
- [CLI 版本不可用] → 关于页显示不可用状态，仍展示其他应用信息。

## Migration Plan

1. 新安装和旧安装默认使用简体中文；首次保存时创建语言偏好文件。
2. 升级不触碰会话、Claude 用户配置或外观偏好文件。
3. 回滚时新增语言偏好文件被旧版本忽略，界面恢复旧有中文文案。
