## Purpose

在桌面图形界面中与 Claude Code 进行对话交互：用户输入消息后经由本地 `claude` CLI 子进程获得回复，界面以流式方式渲染回复内容与中间过程，并处理错误与中断。

## ADDED Requirements

### Requirement: 发送消息并获得回复

系统 SHALL 允许用户在图形界面的输入框中输入文本消息，提交后经由本地 `claude` CLI 子进程处理，并将 Claude Code 的回复展示在当前会话的消息区。

#### Scenario: 成功发送并收到回复

- **WHEN** 用户在输入框输入非空文本并点击发送（或按下发送快捷键）
- **THEN** 系统在消息区追加一条用户消息，调用 `claude` CLI 处理该输入，并在同一会话中追加渲染 Claude Code 的回复

#### Scenario: 阻止发送空消息

- **WHEN** 输入框内容为空或仅含空白字符时用户触发发送
- **THEN** 系统不发起 CLI 调用，且不在消息区追加任何消息

### Requirement: 流式渲染回复

系统 SHALL 在 Claude Code 生成回复的过程中以流式（逐步追加）方式更新界面，而非等待全部内容生成后一次性展示。

#### Scenario: 回复逐步呈现

- **WHEN** CLI 子进程持续输出回复片段
- **THEN** 系统按到达顺序将片段增量追加到当前回复气泡中，用户无需等待完整回复即可看到进度

### Requirement: 富文本与代码渲染

系统 SHALL 将 Claude Code 回复中的 Markdown 结构（含代码块）渲染为可读的富文本，代码块 SHALL 提供一键复制。

#### Scenario: 渲染代码块并可复制

- **WHEN** 回复内容包含 Markdown 代码块
- **THEN** 系统以等宽字体和语法高亮展示代码块，并提供复制按钮，点击后将代码文本写入系统剪贴板

### Requirement: 展示工具调用等中间过程

系统 SHALL 在会话流中以可区分于普通回复的形式展示 Claude Code 的中间过程事件（如工具调用、文件读写、思考过程），使用户了解 Agent 正在执行的动作。

#### Scenario: 显示工具调用

- **WHEN** Claude Code 在生成回复过程中触发工具调用
- **THEN** 系统在消息流中以独立的、视觉上可区分的条目展示该工具调用的名称与关键信息

### Requirement: 错误处理

当 CLI 调用失败（如 CLI 未安装、认证无效、进程异常退出）时，系统 SHALL 向用户展示可理解的错误提示，并保持应用不崩溃、会话数据不丢失。

#### Scenario: CLI 不可用

- **WHEN** 用户发送消息但本地 `claude` CLI 不存在或无法执行
- **THEN** 系统在界面展示明确的错误提示（说明原因与可能的解决方向），且已有会话与消息保持完好

#### Scenario: 进程异常退出

- **WHEN** CLI 子进程在生成回复过程中以非零状态退出或崩溃
- **THEN** 系统标记该次回复为失败并展示错误信息，同时保留已接收到的部分内容

### Requirement: 中断生成

系统 SHALL 允许用户在 Claude Code 正在生成回复时主动中断该次生成。

#### Scenario: 用户中断回复

- **WHEN** 回复正在流式生成且用户点击停止
- **THEN** 系统终止对应的 CLI 子进程，停止继续追加内容，并将该消息标记为已中断，界面恢复到可再次发送的状态

### Requirement: 工具权限确认

当 Claude Code 在无头模式下请求执行需要授权的敏感操作（如执行命令、写入/修改文件、访问网络）时，系统 SHALL 在界面呈现该权限请求，等待用户决定（允许/拒绝），并将决定回传给 Claude Code，使生成得以继续或按拒绝处理。系统 SHALL NOT 在无人确认的情况下静默放行敏感操作，也不得因等待确认而使界面无响应。

#### Scenario: 展示权限请求并允许

- **WHEN** Claude Code 请求执行一项需要授权的敏感操作
- **THEN** 系统在会话流中以可区分的形式展示该请求（操作类型与关键信息），提供允许/拒绝选项；用户选择允许后，系统将决定回传，Claude Code 继续执行并推进回复

#### Scenario: 拒绝权限请求

- **WHEN** 用户对某权限请求选择拒绝
- **THEN** 系统将拒绝决定回传给 Claude Code，该敏感操作不被执行，会话据此继续或结束，界面保持可交互

#### Scenario: 等待确认期间界面不假死

- **WHEN** 存在未决的权限请求
- **THEN** 界面明确提示存在待确认项且保持响应（可查看、可取消/停止本次生成），不出现无提示的卡死状态

### Requirement: 危险放行开关显式化

若系统提供「跳过权限确认/全部放行」这类降低安全约束的选项，该选项 SHALL 显式呈现、默认关闭，并向用户说明风险；默认行为 SHALL 采用更安全的一侧（逐次确认或最小授权）。

#### Scenario: 默认采用安全侧

- **WHEN** 用户未主动开启任何降低约束的选项
- **THEN** 系统默认对敏感操作逐次请求确认，而非默认全部放行

#### Scenario: 开启放行需显式且带风险提示

- **WHEN** 用户尝试开启「跳过确认/全部放行」
- **THEN** 系统以显式操作开启并展示风险说明，且该状态可随时关闭
