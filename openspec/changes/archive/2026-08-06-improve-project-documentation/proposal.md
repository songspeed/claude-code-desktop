## 为什么

当前 `README.md` 只有项目标题，新开发者无法从仓库入口了解运行前置条件、启动方式、主要能力、数据位置或常见故障处理。项目说明分散在 `CLAUDE.md`、`docs/design.md`、`docs/ai-usage.md` 和 `docs/validation-matrix.md`，其中部分目录、版本、打包输出和验收状态已经随实现演进而不一致。现在补齐文档入口并建立维护边界，可以降低上手成本，也能让后续实现、验收和发布有统一的事实来源。

## 变更内容

- 重写 `README.md`，提供项目定位、功能概览、系统要求、Claude CLI 前置配置、安装与开发命令、测试/构建/打包流程、数据与安全说明，以及详细文档索引。
- 新增面向使用者的 `docs/getting-started.md`，说明首次运行、Claude 可执行文件检查、项目目录关联、会话和设置的基本使用路径。
- 新增面向贡献者的 `docs/development.md`，说明源码分层、IPC 边界、状态与持久化约定、测试策略、调试流程和提交前检查清单。
- 新增 `docs/troubleshooting.md`，集中记录 CLI 找不到、PATH 不完整、项目目录无效、流式输出异常、数据文件位置和跨平台打包问题的排查步骤。
- 更新 `docs/design.md` 的目录、依赖版本、架构描述和数据流，使其与当前 `electron/`、`src/` 和 `tests/` 实现一致，并链接到新文档。
- 更新 `docs/validation-matrix.md` 的命令、产物目录、已验证范围和待验证项，明确单元测试、桌面预览与三端实机验收的区别。
- 保留 `docs/ai-usage.md` 作为开发记录，并在 README 文档索引中标注其历史性质，避免将过程记录误认为用户指南。
- 文档示例统一使用可复制的 npm 命令、平台路径和当前脚本名称；不修改应用运行逻辑、IPC 接口、依赖或打包配置。

## 能力范围

### 新增能力

- 无。该变更只补充和校正文档，不引入可由系统或用户调用的新运行时行为。

### 修改能力

- 无。现有 OpenSpec 能力规格的运行时要求不变；本变更通过 `skip_specs: true` 声明为纯文档维护。

## 影响

- 影响文件：根目录 `README.md`、`docs/` 下的使用、开发、架构、排障和验收文档，以及本变更的 OpenSpec 规划文件。
- 不影响源码、IPC/API 契约、用户数据格式、依赖版本和构建产物。
- 文档需要以 `package.json`、实际源码目录、现有测试和 Electron 用户数据路径为事实依据；涉及版本或命令时应在后续实现和发布前复核。
- 完成后，README 作为入口索引，使用指南服务于首次使用者，开发指南服务于贡献者，设计与验收文档服务于维护和发布，AI 使用说明继续仅记录开发过程。
