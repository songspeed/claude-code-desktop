## MODIFIED Requirements

### Requirement: 流式渲染回复

系统 SHALL 在 Claude Code 生成回复的过程中以流式(逐步追加)方式更新界面,而非等待全部内容生成后一次性展示。系统 SHALL 按事件到达顺序呈现同一回合内的内容:当回复文本与中间过程事件(如工具调用)交替出现时,已产生的文本 SHALL 在下一个中间过程事件到达前先定格为独立的消息条目,使文本与中间过程条目的先后顺序与实际发生顺序一致,且不同片段的文本 SHALL NOT 被合并进同一条目。

#### Scenario: 回复逐步呈现

- **WHEN** CLI 子进程持续输出回复片段
- **THEN** 系统按到达顺序将片段增量追加到当前回复气泡中,用户无需等待完整回复即可看到进度

#### Scenario: 文本与工具调用交替时顺序正确

- **WHEN** 同一回合内 Claude Code 先输出一段文本,随后触发工具调用,再输出后续文本
- **THEN** 系统按「前段文本条目 → 工具调用条目 → 后段文本条目」的实际发生顺序依次呈现,前段与后段文本分属不同的消息条目,不被合并

### Requirement: 展示工具调用等中间过程

系统 SHALL 在会话流中以可区分于普通回复的形式展示 Claude Code 的中间过程事件(如工具调用、文件读写、思考过程),使用户了解 Agent 正在执行的动作。中间过程条目 SHALL 出现在其实际发生的位置——即位于该事件之前产生的回复文本之后、之后产生的回复文本之前。

#### Scenario: 显示工具调用

- **WHEN** Claude Code 在生成回复过程中触发工具调用
- **THEN** 系统在消息流中以独立的、视觉上可区分的条目展示该工具调用的名称与关键信息

#### Scenario: 工具调用条目位置与发生顺序一致

- **WHEN** 一个工具调用发生在两段回复文本之间
- **THEN** 该工具调用条目在消息流中位于前一段文本条目之后、后一段文本条目之前,而非被前置到本回合所有文本之前

### Requirement: 错误处理

当 CLI 调用失败(如 CLI 未安装、认证无效、进程异常退出)时,系统 SHALL 向用户展示可理解的错误提示,并保持应用不崩溃、会话数据不丢失。当错误发生在回复已部分生成之后时,系统 SHALL 保留并展示已接收到的部分回复内容,再追加错误提示,行为与用户主动中断时保留部分内容保持一致。

#### Scenario: CLI 不可用

- **WHEN** 用户发送消息但本地 `claude` CLI 不存在或无法执行
- **THEN** 系统在界面展示明确的错误提示(说明原因与可能的解决方向),且已有会话与消息保持完好

#### Scenario: 进程异常退出

- **WHEN** CLI 子进程在生成回复过程中以非零状态退出或崩溃
- **THEN** 系统标记该次回复为失败并展示错误信息,同时保留已接收到的部分内容

#### Scenario: 出错时保留已流式呈现的部分文本

- **WHEN** Claude Code 已流式输出若干文本后,本次生成因错误终止
- **THEN** 系统将已接收的部分文本保留为一条独立的回复条目,随后再追加错误提示条目,已呈现的文本不被清空丢弃
