# gui-chat Specification

## Purpose

在桌面图形界面中与 Claude Code 进行对话交互：用户输入消息后经由本地 `claude` CLI 子进程获得回复，界面以流式方式渲染回复内容与中间过程，并处理错误与中断。

## Requirements

### Requirement: 发送消息并获得回复

系统 SHALL 允许用户在图形界面的输入框中输入文本消息，提交后经由本地 `claude` CLI 子进程处理，并将 Claude Code 的回复展示在当前会话的消息区。

#### Scenario: 成功发送并收到回复

- **WHEN** 用户在输入框输入非空文本并点击发送（或按下发送快捷键）
- **THEN** 系统在消息区追加一条用户消息，调用 `claude` CLI 处理该输入，并在同一会话中追加渲染 Claude Code 的回复

#### Scenario: 阻止发送空消息

- **WHEN** 输入框内容为空或仅含空白字符时用户触发发送
- **THEN** 系统不发起 CLI 调用，且不在消息区追加任何消息

### Requirement: 流式渲染回复

系统 SHALL 在 Claude Code 生成回复的过程中以流式方式更新当前回合，而非等待全部内容生成后一次性展示。系统 SHALL 按事件到达顺序呈现正文、活动组和通知：当回复文本与中间过程事件交替出现时，事件之前的正文 SHALL 定格在对应位置；连续中间过程事件 SHALL 在不改变其内部顺序的前提下收纳为活动组，而非为每个工具调用创建割裂的普通消息气泡。

#### Scenario: 回复逐步呈现

- **WHEN** CLI 子进程持续输出回复片段
- **THEN** 系统按到达顺序将片段增量追加到当前回合的正文中，用户无需等待完整回复即可看到进度

#### Scenario: 文本与工具调用交替时顺序正确

- **WHEN** 同一回合内 Claude Code 先输出一段文本，随后触发一个或多个工具调用，再输出后续文本
- **THEN** 系统按「前段正文 → 对应活动组 → 后段正文」的实际发生顺序呈现，活动组内工具调用顺序与实际发生顺序一致

### Requirement: 富文本与代码渲染

系统 SHALL 将 Claude Code 回复中的 Markdown 结构（含代码块）渲染为可读的富文本，代码块 SHALL 提供一键复制。

#### Scenario: 渲染代码块并可复制

- **WHEN** 回复内容包含 Markdown 代码块
- **THEN** 系统以等宽字体和语法高亮展示代码块，并提供复制按钮，点击后将代码文本写入系统剪贴板

### Requirement: 展示工具调用等中间过程

系统 SHALL 在会话流中以可区分于普通回复的活动组展示 Claude Code 的中间过程事件。活动组 SHALL 优先展示简洁且可理解的摘要，并提供可访问的展开控制以查看底层传输实际提供的详情；系统 SHALL NOT 将工具调用描述、系统状态或原始输入混入助手 Markdown 正文。

#### Scenario: 显示工具调用摘要

- **WHEN** Claude Code 在生成回复过程中触发工具调用
- **THEN** 系统在该工具调用实际发生的位置显示所属活动组和可确定的操作摘要，用户可展开查看单项活动

#### Scenario: 工具调用详情不可用

- **WHEN** 底层传输未提供某工具调用的结果或可展示详情
- **THEN** 系统在活动组中说明详情不可用或活动已发起，不显示推测的执行结果

### Requirement: 错误处理

当 CLI 调用失败(如 CLI 未安装、认证无效、进程异常退出)时,系统 SHALL 向用户展示可理解的错误提示,并保持应用不崩溃、会话数据不丢失。当错误发生在回复已部分生成之后时,系统 SHALL 保留并展示已接收到的部分回复内容,再追加错误提示,行为与用户主动中断时保留部分内容保持一致。

#### Scenario: CLI 不可用

- **WHEN** 用户发送消息但本地 `claude` CLI 不存在或无法执行
- **THEN** 系统在界面展示明确的错误提示(说明原因与可能的解决方向),且已有会话与消息保持完好

#### Scenario: 进程异常退出

- **WHEN** CLI 子进程在生成回复过程中以非零状态退出或崩溃
- **THEN** 系统标记该次回复为失败并展示错误信息,同时保留已接收到的部分内容

#### Scenario: 出错时保留已流式呈现的部分文本

- **WHEN** Claude Code 已流式输出若干文本后,本次生成因错误终止
- **THEN** 系统将已接收的部分文本保留为一条独立的回复条目,随后再追加错误提示条目,已呈现的文本不被清空丢弃

### Requirement: 中断生成

系统 SHALL 允许用户在 Claude Code 正在生成回复时主动中断该次生成。

#### Scenario: 用户中断回复

- **WHEN** 回复正在流式生成且用户点击停止
- **THEN** 系统终止对应的 CLI 子进程，停止继续追加内容，并将该消息标记为已中断，界面恢复到可再次发送的状态### Requirement: 工具权限确认

当 Claude Code 在无头模式下请求执行需要授权的敏感操作（如执行命令、写入/修改文件、访问网络）时，系统 SHALL 在界面呈现该权限请求，等待用户决定（允许/拒绝），并将决定回传给 Claude Code，使生成得以继续或按拒绝处理。系统 SHALL NOT 在无人确认的情况下静默放行敏感操作，也不得因等待确认而使界面无响应。

#### Scenario: 展示权限请求并允许

- **WHEN** Claude Code 请求执行一项需要授权的敏感操作
- **THEN** 系统在会话流中以可区分的形式展示该请求（操作类型与关键信息），提供允许/拒绝选项；用户选择允许后，系统将决定回传，Claude Code 继续执行并推进回复

#### Scenario: 拒绝权限请求

- **WHEN** 用户对某权限请求选择拒绝
- **THEN** 系统将拒绝决定回传给 Claude Code，该敏感操作不被执行，会话据此继续或结束，界面保持可交互

#### Scenario: 等待确认期间界面不假死

- **WHEN** 存在未决的权限请求
- **THEN** 界面明确提示存在待确认项且保持响应（可查看、可取消/停止本次生成），不出现无提示的卡死状态

### Requirement: 危险放行开关显式化

若系统提供全部放行这类降低安全约束的选项，该选项 SHALL 以会话级授权模式显式呈现，并在切换到该模式前向用户说明风险且要求确认。新会话 SHALL 默认采用自动接受编辑模式；用户未确认时系统 SHALL NOT 启用全部放行。

#### Scenario: 新会话采用默认授权模式

- **WHEN** 用户新建一个会话且未选择任何授权模式
- **THEN** 系统为该会话采用自动接受编辑模式，而非全部放行

#### Scenario: 启用全部放行需确认

- **WHEN** 用户尝试将当前会话切换到全部放行
- **THEN** 系统展示风险说明并仅在用户确认后启用该模式

### Requirement: 显示聊天项目上下文
系统 SHALL 在聊天工作区和组合器上下文区显示当前会话的项目关联状态，并提供选择或更改项目目录的明确入口。生成期间目录控制 SHALL 禁用，避免运行中的会话上下文发生变化。

#### Scenario: 已关联目录的上下文可见
- **WHEN** 用户查看一个已关联项目目录的会话
- **THEN** 系统显示项目目录名称，且用户可以查看完整路径、切换目录或在系统文件管理器中显示该目录

#### Scenario: 未关联目录的引导
- **WHEN** 用户查看一个未关联项目目录的空会话
- **THEN** 系统在主要工作区提供选择项目目录的操作，并提示用户关联目录后才能开始任务

### Requirement: 输入状态与提示

系统 SHALL 根据当前会话项目目录、Claude Code CLI 可用性和生成状态更新输入框的可用性及提示文案。系统 SHALL 在缺少项目目录或 CLI 不可用时阻止发送；生成期间 SHALL 显示可停止的生成提示。

#### Scenario: 项目与 CLI 均可用时提示任务输入

- **WHEN** 当前会话已关联项目目录、Claude Code CLI 可用且未生成回复
- **THEN** 输入框可编辑，并提示用户描述任务或引用项目文件

#### Scenario: 缺少前置条件时阻止输入

- **WHEN** 当前会话未关联项目目录或 Claude Code CLI 不可用
- **THEN** 输入框不可编辑，并显示对应的项目目录或 CLI 可用性提示

#### Scenario: 生成期间提示状态

- **WHEN** Claude Code 正在生成回复
- **THEN** 输入框不可编辑，并显示正在生成且可停止的提示

### Requirement: 工具权限确认

系统 SHALL 在组合器中提供会话级授权模式，以控制无头 Claude Code CLI 对工具操作的处理方式。系统 SHALL 使用已选择的模式启动当前会话后续请求，而 SHALL NOT 在当前传输层无法可靠回传决定时承诺逐工具确认；生成期间界面仍 SHALL 保持响应并允许用户停止本次生成。

#### Scenario: 使用会话授权模式处理工具

- **WHEN** 用户以某一授权模式发送消息且 Claude Code 需要执行工具操作
- **THEN** 系统以该会话授权模式调用 Claude Code CLI，并在消息流中持续展示生成状态和工具事件

#### Scenario: 生成期间可停止

- **WHEN** Claude Code 正在按会话授权模式执行或生成回复
- **THEN** 用户可以停止本次生成，界面恢复到可再次发送的状态

### Requirement: 尊重用户的消息阅读位置

系统 SHALL 仅在用户位于消息区域底部或接近底部时自动跟随流式输出。当用户滚动查看较早内容时，系统 SHALL 保持其阅读位置，并在有新输出时提供跳转到最新输出的可访问操作。

#### Scenario: 用户正在阅读历史消息

- **WHEN** 用户将消息区域滚动到距离底部较远的位置且新正文或活动到达
- **THEN** 系统不改变当前滚动位置，并显示可跳转到最新输出的操作

#### Scenario: 用户位于最新输出位置

- **WHEN** 用户位于消息区域底部或接近底部且新正文或活动到达
- **THEN** 系统自动跟随到最新输出，用户持续看到当前生成状态
